# 产业朝闻

根据用户指定的发布日完成新闻抓取、选题、核源、摘要和公众号排版。默认目标新闻日为发布日前一日；用户指定抓取时间窗时严格按其要求执行。宏观政策优先选目标新闻日当天发布的政策；目标日（尤其周末、节假日）当天确实没有新发布条例时，允许用目标日前最多3日内由官方公布、且在目标日仍处媒体集中解读期的国家可执行条例补位，须官网核验（official_source: true）并在note披露实际发布日期，渲染器打印补位披露；超过3日或无官网正文的旧政策一律不得使用。宏观政策入选标准：国家（中央部委及以上）发布的可执行条例、办法、通知、方案、规划等制度文件，不得用领导人讲话、国际会议宣言、座谈会纪要等非制度性内容充数。

## 最终交付

成稿必须交付三个独立文件：

1. `产业朝闻_YYYY-MM-DD_公众号排版.html`：可直接复制到 135 编辑器源码模式。正文只保留 `【来源】`，不出现新闻网址。
2. `产业朝闻_YYYY-MM-DD_HTML代码.txt`：完整HTML源码，与HTML文件UTF-8内容完全一致，无Markdown围栏、无省略，便于打开复制。
3. `产业朝闻_YYYY-MM-DD_原链接核查表.md`：列出全部入选新闻的栏目、标题、公开精度的发布时间、来源、原链接、时间窗口判断、核查备注和来源分布。

抓取报告、完整新闻池、候选评分等属于内部工作文件，可以在执行过程中生成，但不作为最终交付物展示给用户。

回复同时提供完整HTML代码块，便于复制到135源码模式，不能只给文件链接或省略未修改栏目；用户明确只要文件时除外。HTML文件本身不含Markdown围栏。复盘请求交付复盘与Skill修改结果，不覆盖已叫停的稿件。

## 用户提供 HTML 的排版优化

用户提供 HTML 实验稿并要求优化排版时，进入本模式，不抓取新闻、不重新选题、不改写新闻内容。后续正常制作朝闻仍执行完整抓取和选题流程。

- 保留用户 HTML 中的全部新闻文字、标题长度、日期、来源标签、栏目顺序、新闻条数和图片地址，只修改明确要求的排版。
- 使用 scripts/normalize_layout.py 处理 HTML：标题从左边界开始自然换行，非末行两端对齐到正文右边界，末行和短标题自然左对齐。
- 标题及其嵌套 span/strong 的字距固定为0，正文保持原有字号、行高和字距；不得右对齐整段标题、不得补空格、不得手动断句、不得缩短标题。
- 必须用实际 HTML 在375、390、430像素宽度检查长标题、短标题、数字和括号标题，确认没有溢出、遮挡或标题正文边界不一致。
- 该模式只输出优化后的 HTML、同内容 TXT 和手机预览，不生成虚构新闻。

## 执行流程

1. 确认发布日、目标新闻日和抓取窗口。用户只说“做 X 日产业朝闻”时，发布日为 X 日，主选 X 日前一自然日的新闻；默认抓取窗口为目标新闻日 00:00 至发布日制作时刻，并把目标新闻日前一日 18:00 后内容仅作为补充池。宏观政策栏不用补充池凑数，优先从目标新闻日当天检索；目标日无合格条例时按文件头部规则用目标日前3日内官网核验的可执行条例补位并披露。
2. 运行 `scripts/chanye_zaowen.py` 抓取财联社和科创板日报完整分页新闻池。周末、节假日或新闻明显不足时加 `--include-wscn`。
3. 做公开补充检索和核源。宏观政策必须核对官方网站；国内重大工程、产业金融、龙头企业及其领导人的产业新闻必须主动补检。普通工作日不把华尔街见闻当作固定主池。
4. 建立完整候选池、去重并先做红线排除；逐条读取 [退回案例库](references/rejected-cases.md)，按“来源、标题、栏目、价值、重复、核验”六类检查。命中同类案例的候选直接淘汰或从严判断，不能等用户退回后再改。
5. 读取 [选题优先级规则](references/selection-priority.md)，按吸引力、产业价值、栏目适配、目标日优先和来源可信度完成最终选择。自动评分只能辅助排序，不能替代人工语义判断。
6. 每条候选在入选前必须保留源标题、原文来源证据、发布时间和承载链接；缺少任一项先补核，不得凭抓取平台名称猜来源。每条摘要只压缩已有事实，保留主体、动作、时间、关键数字和结果，不扩写意义，不补充原文没有的判断。
7. 将最终入选新闻写成渲染器要求的JSON，运行 `scripts/render_135.py`，以固定母版生成HTML、完整源码TXT、来源链接核查表三个最终文件。
8. 运行 `scripts/preflight_check.py` 做机器自检（**强制步骤，不得跳过**）：
   `python scripts/preflight_check.py --selected selected.json --pool pool/完整新闻池.json --out-dir output --stamp YYYY-MM-DD`
   覆盖：来源标签与原文括号/“据XX”标注一致性、标题与源标题一致性、链接可达性（404即错误）、禁用串、HTML/TXT字节一致（自动识别预览面板注入并放行）、来源集中度与独立域名数、宏观 official_source/日期/红线词、跨栏重复选题、价值观红线词。**错误数必须为 0 才能交付**；警告项逐条人工确认并在核查表标注。离线时加 `--skip-links` 并说明。
9. 人工终检：机器查不了的语义问题（栏目边界、产业相关性、信息增量、摘要是否扩写）。任何一条时间不明、原链接打不开、来源与链接不匹配、摘要疑似扩写、来源标签不是单一发布者名称、来源集中超过一半、栏目明显错误时，先修正再交付。
10. 仅在用户明确要求复盘时，按 [复盘规则](references/daily-review.md) 记录实际问题和证据；不自动每日复盘，也不默认在每次交付后启动复盘。

## 新闻池与来源

- 财联社：基础完整新闻池，必须按时间窗口完整分页抓取。
- 科创板日报：硬科技增强池，必须使用官网列表接口完整分页抓取。
- 华尔街见闻：仅在周末、节假日或新闻不足时作为补充池。
- 公开权威/财经媒体检索：用于核源、补足事实或补充高价值选题，不替代主池完整抓取。
- 公众号文章：只有用户主动提供具体链接、截图或正文时才作为补充参考，不作为固定新闻池。

来源优先级：官方网站 > 国家级或地方级权威媒体 > 财联社、科创板日报及其他可靠财经媒体。

来源标签写实际发布渠道。**新闻标题硬规则（2026年9月13日反馈新增）**：入选新闻的标题一律使用源标题（原文标题），不得自行改写或另拟，尤其是短标题新闻——来源标题是什么就用什么。仅在自拟标题明显比源标题更有吸引力时才可改，且须在核查表备注中写明改写理由；源标题含"今天/昨日"等相对时间词、刊发日会失真时，可去掉时间词并在备注披露。用户明确指定标题的条目以用户为准。**来源标签判定硬规则（2026年9月13日反馈新增，逐条强制执行）**：凡原文末尾括号标注来源（如“（央视新闻）（央视财经）（证券时报）（界面）（上证报）”），或正文明确写“据XX报道/消息”“XX称”“XX发布的最新消息”的，标签一律直接写该被标注的原始来源（如【央视新闻】【证券时报】【界面新闻】【上海证券报】【波音公司网站】）；抓取平台（财联社电报、科创板日报、华尔街见闻等）只是承载渠道，其标签仅在它自己是原始报道者且未标注其他来源时使用。逐条自检方法：看每条入选新闻原文的最后括号和“据XX”表述，出现即换标签，承载关系写入核查表备注，链接仍用已核验的承载链接。交付前对全部条目跑一遍该检查，连续漏判两条即视为交付事故。公司确实在官网发布时可写“公司官网／公司新闻稿”，不能仅因公司是新闻主体就把公司名当来源。转载时方括号内只写原来源发布者名称，转载与承载关系写入核查表备注，不得写进标签（渲染器会拒绝含括号、转引、转载字样的来源标签）。HTML 中每条新闻正文末尾格式固定为“……【财联社】”这种形式：方括号内只写实际发布者名称，不写“来源”、不写“转引”、不写“转载”、不写括号说明。摘要不得自行添加任何来源标签，统一由渲染器追加一次；链接只写入原链接核查表。

宏观政策必须提供政府、部委或政策发布机构官网可核对的正文，财经媒体转引不能代替官网核查；关键事实在附件时也核对附件。非gov.cn域名的官方机构页面需人工核实所有权，在JSON标 `official_source: true` 并在 `note` 记录依据；该标记不等于程序核验了真实性。

财联社和科创板日报是线索池，不是所有稿件的默认终点。每次统计原始发布者和承载域名分布，同稿跨站转载不算独立来源。最终成稿中，财联社/科创板日报承载链接不得超过全部新闻的一半，且至少使用3个非这两家平台的独立承载域名；达不到就继续核源，不得直接交付。其他栏目也主动使用政府官网、公司官网、央视、新华社、地方权威媒体及可靠财经媒体，不靠换标签制造多样性，不为分散来源牺牲真实性。

## 栏目

栏目顺序固定为：

1. 热点资讯 `HOT NEWS`
2. 国际资讯 `INTERNATIONAL NEWS`
3. 国内资讯 `DOMESTIC NEWS`
4. 企业动态 `COMPANY NEWS`
5. 宏观政策 `MACRO POLICIES`

硬性最低数量：热点资讯≥3条、国际资讯≥3条、国内资讯≥4条、企业动态≥6条、宏观政策≥3条，共至少19条。这是逐栏下限，不是固定配额，也不是上限。有合格新闻就继续增加，不能达到最低数量后截断。各栏不得相互抵消缺口。质量不足应继续补检；确实无法满足时明确报告未完成及缺口，不能编造、低质凑数或静默少交。渲染器逐栏强制校验，不提供降额开关。

详细分类、优先级和红线以 [选题优先级规则](references/selection-priority.md) 为准。

## 栏目边界与选题红线（2026年9月13-14日用户反馈固化）

**栏目边界判定表**（拿不准时按此表归栏，一律不得混栏）：

| 内容形态 | 归栏 | 典型反例（曾被用户退回） |
| --- | --- | --- |
| 国家/部委发布的可执行制度文件：条例、办法、通知、实施方案、规划（带施行日期或具体量化目标） | 宏观政策 | — |
| 领导讲话、倡议、宣言、会议/座谈会、答记者问、吹风会 | 国际资讯（涉外）或国内资讯；**不得进宏观政策** | 金砖五项倡议、新德里宣言、具身智能座谈会 |
| 中国境内产业基建、科研平台、地方项目、工程节点 | 国内资讯 | — |
| 海外主体（企业/机构）的投资、技术、经营、政策动向 | 国际资讯 | 美国柴油价格（涉美农业成本，归国际） |
| 企业主体的产品/订单/产能/IPO/财报/人事 | 企业动态 | — |
| 战争冲突、袭击、航道封锁本身 | **不选**（除非明确落到产业成本/供应链且有量化事实） | 沙特输油管道遭袭、美军封锁致99艘商船改道 |

**选题价值五问**（任一不过就淘汰；preflight 已内置红线词提示）：
1. 与产业/企业经营有关吗？（纯地缘冲突、纯股价、纯时政活动→淘汰）
2. 有真实信息增量吗？（一句话预告、活动预告、仪式类→淘汰）反例：特斯拉10月1日活动预告、小米澎程全国交付。
3. 是软文式活动吗？（交付仪式、庆祝、周年、揭牌→淘汰）
4. 主体是中国产业利益相关方吗？（涉外主体→进国际栏）
5. 同日同主题只留信息量最大的一条；后续进展替换前一条，不并存。反例：霍尔木兹“达成一致”与外长采访并存、两条AI主题国际新闻并存、德拉吉与拉加德混淆。

**跨栏去重**：交付前用 preflight 的相似度检查过一遍，同主题≥0.55 相似度的条目必须合并或替换。

企业动态：苹果、台积电、小米等大公司，以及其领导人的产业相关新闻默认优先入选，不仅限于重大投资或技术突破。产品、经营、供应链、业务战略、行业判断等有可核实产业事实均可选。该名单不是封闭名单；不能因企业栏已达6条而排除合格的龙头新闻，可增加条数。仅排除重复、私人生活、纯股价、无产业关联或无法核实的内容，保留消息来源和不确定性。

## 135 排版

生成排版稿前读取 [135 排版规则](references/135-layout.md)。必须使用 `assets/135-wechat-template.html`：

- 只替换日期、星期、栏目文字和新闻内容。
- 不改变头图城市图、白色文字卡片、投影、栏目标题条、新闻卡片、结尾文案和尾图样式。
- 城市图和尾图使用母版中的微信素材地址；禁止使用带 `auth_key` 的 135 临时链接、本地路径或临时外链。
- HTML文件是135源码片段，不含Markdown围栏；回复展示完整源码时使用html代码块。

## 渲染输入

传给 `scripts/render_135.py` 的 JSON 结构：

```json
{
  "publish_date": "2026-09-09",
  "items": {
    "热点资讯": [
      {
        "title": "新闻标题",
        "summary": "仅根据原文压缩的摘要。",
        "source": "财联社",
        "published_at": "2026-09-08 20:10:00",
        "url": "https://example.com/original",
        "time_check": "目标新闻日",
        "note": "链接可访问；时间与正文已核对"
      }
    ]
  }
}
```

五个栏目键均应存在。`url` 只能写实际核验过的原始或可靠承载链接。

`published_at` 保留原页面公开精度，允许YYYY-MM-DD，不补造时分秒。核查备注区分事件日、原始发布日期、转载时间，不能用今日转载包装旧闻。用户指定保留的旧闻或传闻注明例外及不确定性。

执行示例：

```powershell
python scripts/render_135.py --input selected.json --out-dir output
```

## 最终自检

先跑机器自检，再人工看语义：

```bash
python scripts/preflight_check.py --selected selected.json --pool pool/完整新闻池.json \
    --out-dir output --stamp YYYY-MM-DD
```

- 错误数必须 0 才交付；警告逐条人工确认并在核查表备注。`--strict` 可把警告也视为错误（用于重要稿件）。
- preflight 覆盖：来源标签 vs 原文括号/“据XX”标注、标题 vs 源标题、链接可达性（非200即错误）、禁用串、HTML/TXT字节一致（自动放行预览面板注入）、承载集中度与独立域名数、宏观 official_source/日期披露/红线词、跨栏重复选题、价值红线词。
- 机器查不了的：栏目边界、产业相关性、信息增量、摘要是否扩写、标题是否真的更吸引人——仍需人工逐条过。

- HTML 与核查表中的新闻标题、来源和顺序逐条一致。
- HTML 不包含 `http://`、新闻超链接或裸网址；两张固定图片的微信素材 URL 除外。
- 核查表每条新闻都有可点击原链接和明确发布时间；时间无法确认的新闻不得入选。
- HTML 不包含 `auth_key`、`bexp.135editor.com` 或 `file:`。
- 政策未误放热点或国内，普通海外企业新闻未误放国际，单一企业公告未误放国内。
- 新闻真实存在，摘要可由来源逐句支持，没有编造、推断或扩写。
- 各栏分别达到≥3/≥3/≥4/≥6/≥3，超额条目完整保留，宏观全部官网，来源集中度已检查。
- 局部替换只改指定位置并同步三个文件，保留其他条目与母版。同一来源两轮检索无结果时，普通新闻可用明确转引的可靠页面并披露限制；宏观无官网则换题或报告缺口。不对同一网址无界重试，进度区分已核查、未写入、已生成、已验证。
- 三个文件均存在；HTML和源码TXT字节一致；核查表标题、来源、顺序与正文逐条一致。
- 退回案例六类检查全部完成；来源标签只写实际发布者名称，标题默认与源标题一致；标题非末行右边界与正文一致，末行自然左起。
